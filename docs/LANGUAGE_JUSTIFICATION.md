# Language justification

Current evidence does not justify inventing a new programming language. A configured Pysa run independently detects the elementary P1 and P2 flows (see `BASELINE_COMPARISON.md`). Static information flow, effect typing and capabilities are established techniques; Python's open-world dynamism limits unconditional proofs. A useful next step is a restricted Python subset plus audited capability interfaces and a runtime enforcement point, with measured unknown rates. Only if those restrictions impose unacceptable escape hatches or ergonomics should a language be considered. The smallest potential language requirements are sealed capability imports and nonforgeable effect tokens; typed confidentiality/integrity labels with explicit declassification and endorsement; and approval tokens tied to a specific action and payload. These are semantic requirements, not proposed syntax. Even such a language cannot prove human intent, model truthfulness or external-service behavior.
